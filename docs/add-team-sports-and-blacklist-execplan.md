# Add Team Sports and Blacklist Unsupported Sports

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must stay current while the work is in progress. It follows `PLANS.md` from the repository root.

## Purpose / Big Picture

BracketIQ must only advertise sports that its tournament and league match engine can score. After this change, affiliate imports and event creation can use Field Hockey, Lacrosse, Table Tennis, Australian Football, Ball Hockey, and Futsal as canonical sports. Each sport will have age and skill division choices where appropriate, scoring rules, incident types, timekeeping, and official positions. Cheerleading, Dance, Running, Swimming, Track and Field, and Golf will remain outside the `Sports` catalog and will be explicitly blacklisted so agents route those source labels to review instead of creating invalid events or organizations.

The result is visible in the sport selector and in the live `Sports` table. A human can verify that the six supported names have complete configuration and that an agent draft containing an excluded name receives a blacklist review error.

## Surprises & Discoveries

- The live catalog is seeded from `src/server/defaultSports.ts`, but affiliate publication resolves names against the database `Sports.name` value. Both code defaults and the database migration are required.
- Skill division options are generated by `getSkillDivisionTypeOptionsForSport` in `src/lib/divisionTypes.ts`. Adding a sport row without adding a matching catalog entry would silently give it generic divisions.
- Affiliate candidates already quarantine missing catalog names. The blacklist therefore needs to classify the reason and strengthen agent guidance; it must not add blacklisted names to `Sports`.

## Decision Log

- Decision: Add Field Hockey, Lacrosse, Table Tennis, Australian Football, Ball Hockey, and Futsal as exact canonical names. Rationale: these are the remaining team sports from the requested set that can use the existing periods, sets, or points scoring models. Date/Author: 2026-08-06, Codex.
- Decision: Normalize `Australian Rules Football` to the canonical `Australian Football` only when an agent or migration has an explicit source mapping; do not add the former spelling as a second catalog row. Rationale: the catalog must have one stable name per sport. Date/Author: 2026-08-06, Codex.
- Decision: Blacklist exact excluded sport labels in shared affiliate validation and keep them absent from `Sports`. Rationale: exclusion is a product rule, not an alternative sport mapping, so an agent must send the source to review rather than guess or publish it. Date/Author: 2026-08-06, Codex.
- Decision: Use idempotent `INSERT ... ON CONFLICT` SQL for the live catalog migration and preserve candidate source data while moving blacklisted candidates to review. Rationale: reruns must be safe and source evidence must remain available for audit. Date/Author: 2026-08-06, Codex.

## Outcomes & Retrospective

The six new canonical rows are live: Field Hockey, Lacrosse, Australian Football, Ball Hockey, Futsal, and Table Tennis. Each row has sport-specific skill divisions, official positions, and a match template. The live catalog increased from 18 to 24 rows, and no excluded sport appears in `Sports`. Three existing candidates, for Golf, Running, and Track and Field, were retained for audit and moved to `NEEDS_REVIEW` with blacklist warnings. No published event, facility, or organization target required quarantine. The migration completed with `ON_ERROR_STOP` and can be replayed safely.

The six excluded names are enforced in code and in the agent prompt. Composite source labels that contain an excluded sport remain non-canonical and continue through the existing human-review path; they are not guessed into a supported sport. No additional work is required for this request.

## Context and Orientation

`src/server/defaultSports.ts` defines the default `Sports` rows. It stores the JSON templates used by event creation and match scoring. `src/lib/divisionTypes.ts` defines the sport-specific division options used to populate `skillDivisionTypes`.

`src/server/affiliateImports/affiliateSportMapping.ts` validates agent-generated candidate and organization sport names against the default catalog. `src/server/affiliateImports/sportQuality.ts` validates stored affiliate rows against the live database catalog. `src/server/affiliateImports/service.ts` resolves canonical names before publication and quarantines invalid candidates.

`src/types/index.ts` exposes the stable sport enum used by older UI components. The Prisma migration under `prisma/migrations/` inserts the six rows and repairs only deterministic source mappings. Production PostgreSQL is reached through the existing operator SSH path documented in `AGENTS.md`; no process restart is part of this task.

## Validation and Acceptance

Each `DEFAULT_SPORTS` row must have a non-empty `skillDivisionTypes`, `officialPositionTemplates`, and `matchRulesTemplate` value. ## Idempotence and Recovery

The migration must use stable IDs equal to canonical names and `ON CONFLICT` updates that fill missing configuration without erasing richer operator changes. Rerunning it must not create duplicate rows. Blacklist remediation must preserve candidate records and source payloads; it changes review status and warnings only. If live verification fails, stop without restarting services and report the failing SQL or query. Do not delete any unrelated candidates, organizations, events, or worktree changes.
